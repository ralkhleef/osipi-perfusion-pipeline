    Documentation

    In one minute

    Every number in a report is one submitted map compared, voxel by voxel, against the organisers' ground truth map for the same scan, inside a region mask. That is the whole idea. The rest of this page is what the column names mean.

    The pipeline does not pass, fail, score or rank anything. It measures and reports. Deciding what counts as good enough belongs to the challenge leads, and nothing on this page is a criterion.

    What each thing is compared against

    In the reportCompared againstWhere the comparison happens
    Parameter maps (Ktrans, vp, CBF, ATT …) The ground truth map for the same scan — same participant, site and repeat Voxel by voxel, whole image and inside each region mask
    Fitted signal (4‑D) The measured signal-time curve for the same scan Residual sum of squares per voxel, across time
    ROI statistics Nothing — these describe the submitted map itself Inside each region mask, one row per scan
    Grouped statistics The same quantity across repeats, sites or participants Across scans, which is why they need more than one

    A row that says Not available means the comparison could not be made, not that it came out badly. The usual reasons are that no ground truth map matched that scan, or that the file was not a parameter map in the first place.

    What the columns mean

    Bias
    Mean of (submitted − reference) across the voxels compared. Signed: positive means the submission reads high on average. Bias near zero does not mean the map is accurate — equal and opposite errors cancel, which is exactly why the regional rows are reported separately from the whole image.
    MAE
    Mean absolute error. The average size of the disagreement, ignoring direction. Unlike bias, errors cannot cancel.
    RMSE
    Root mean squared error. Like MAE but large errors count for more, so it is the one that moves when a few voxels are badly wrong.
    Error CoV
    The spread of the voxelwise errors divided by the reference mean. It is a spread-of-error ratio, not a repeatability coefficient of variation, and the two are easy to confuse because both get called “CoV”. Whole-image values in the hundreds of percent are normal: most of a whole-image volume is background where the reference mean is near zero.
    Corr.
    Pearson correlation between submitted and reference voxels. High correlation with large bias means the pattern is right and the scale is not.
    Within-scan CoV (ROI tables)
    Standard deviation divided by mean inside one region of one scan. This describes how variable the map is within a region. It is not a comparison against ground truth and it is not a repeatability measure.
    Voxels
    How many voxels the number was actually computed from, after non-finite values were excluded. A small count is a reason to treat the row with caution.

    About the 15% figure

    A challenge lead once described “a rough threshold of acceptable performance as having a CoV below 15%”, in the same conversation that ruled out pass/fail and ranking for these challenges.

    Both halves of that matter, so the pipeline treats it as follows:

    • No shipped challenge configures any threshold. Out of the box nothing is flagged, and every report says “not assessed” rather than leaving an ambiguous blank.
    • The mechanism exists. Organisers can set warn_above for a metric in config/validation_rules.yaml, and rows past it are marked for a reviewer to look at.
    • A flag is an annotation and never a verdict. It cannot fail, exclude or reorder a submission, and the underlying value is never rewritten.

    So if you are looking at a 15% figure and wondering whether the pipeline enforced it: it did not, unless somebody put it in the configuration deliberately.

    Telling one row from another

    The DCE-2026 layout gives every scan the same filenames — Ktrans.nii.gz appears once in each of sixty scan folders — so a table keyed on the file name is sixty identical-looking rows.

    Every table and CSV therefore carries the scan as its own column, written as P1 · Site 2 · Repeat 1, and the CSV exports lead with separate participant, site and repeat columns so a spreadsheet can sort and filter on them. A row that reads Not identified is one whose folders did not say which scan it came from.

    What the pipeline will not decide for you

    These are open questions for the challenge leads, and the pipeline reports them as unconfigured rather than picking an answer:

    • Which ICC model. All six Shrout & Fleiss models are implemented; which one applies depends on the study design, so the shipped setting is none and ICC reads “not configured”.
    • Any threshold, including the 15% above.
    • What a methods document must contain, and whether one is required.
    • Region definitions. The masks are the organisers' files; the pipeline reports what is inside them and does not draw them.

    Where two of the supplied masks overlap, statistics inside them are not independent. The DCE mask set is nested this way: every hippocampus voxel also lies inside the grey matter mask, so a grey matter figure includes the hippocampus voxels unless the organisers supply a disjoint mask.
