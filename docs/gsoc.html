    The project

    Python Pipeline for Evaluating OSIPI Perfusion Imaging Challenge Submissions

    By Ranya Al-khleef, mentored by Lena Václavů and Olivia Jones for OSIPI and the ISMRM Perfusion Study Group.

    I built a local web application for reviewing OSIPI perfusion MRI challenge submissions.

    OSIPI works on improving and standardising perfusion imaging methods. Different analysis methods can produce different results from the same MRI data, so challenges are used to compare those methods fairly.

    The pipeline supports DCE, ASL, and DSC submissions and guides reviewers through six steps:

    Upload → Review → Validate → Run → QC & Preview → Export

    It accepts completed result maps or submissions containing code. It checks the files, runs code in Docker when needed, creates QC and previews, and adds ROI statistics or reference comparison when compatible data are available. Results can be exported as blinded reports and structured files.

    The goal is to reduce manual review and apply the same checks to every submission.

    See How it works for the full workflow and Examples for screenshots and example outputs.

    What I built

    Challenge rules such as required maps, file names, dimensions, and dataset structure are configurable. The Configuration Manager tests drafts and saves inactive versions before an organiser activates them.

    Reference maps, ROI masks, and trusted analysis packages can be added when available. QC and previews do not require them.

    See Configuration for more detail.

    How it was built

    The backend uses Python and FastAPI. The interface uses HTML, CSS, and JavaScript.

    Docker runs reproducible submissions. YAML stores challenge rules, and the reporting system creates HTML, PDF, CSV, and JSON outputs.

    The entire application runs locally so challenge data, reference images, masks, and participant submissions can stay on the reviewer's machine.

    Testing and reliability

    Automated backend and frontend tests cover upload, validation, execution, configuration, analysis, reports, exports, and blinding. I also tested real DCE and ASL submissions through the rebuilt Docker application.

    Project result

    The result is a working local workflow from submission files to review and export.

    QC and previews are available for readable maps. DCE Ktrans ROI statistics, generic reference comparison, and provider analysis appear when their required inputs are present.

    Official OSIPI challenge ranking is not currently configured.
