    The project

    Python Pipeline for Evaluating OSIPI Perfusion Imaging Challenge Submissions

    By Ranya Al-khleef, mentored by Lena Václavů and Olivia Jones for OSIPI and the ISMRM Perfusion Study Group.

    This project is a local web application that gives OSIPI challenge organisers and reviewers a more consistent and reproducible way to process perfusion MRI submissions.

    OSIPI works on improving and standardising perfusion imaging methods. Different analysis methods can produce different results from the same MRI data, so challenges are used to compare those methods fairly.

    The pipeline supports DCE, ASL, and DSC perfusion MRI submissions and guides reviewers through a six-step workflow:

    Upload → Review → Validate → Run → QC & Preview → Export

    It can accept completed result maps or reproducible submissions containing code. The app checks the submitted files, runs participant code when needed, reviews NIfTI maps, creates visual previews and QC results, and can provide ROI statistics or reference comparisons when the required data are available. Results can then be exported as blinded reports and structured files for further review.

    The goal is to reduce the amount of manual work needed to review challenge submissions and make the process easier to repeat consistently across different participants.

    See How it works for the full workflow and Examples for screenshots and example outputs.

    Built for challenge review

    A major part of the project was making the pipeline flexible enough to support different perfusion challenges without rewriting the application each time.

    Challenge requirements such as required maps, file names, dataset structure, dimensions, and other rules can be defined through configuration. This allows organisers to adapt the same pipeline for DCE, ASL, DSC, or future challenges.

    Reference maps, ROI masks, and scoring tools can also be added when they are available. General QC and previews still work without them.

    See Configuration for more detail.

    How it was built

    The application uses Python and FastAPI for the backend and HTML, CSS, and JavaScript for the web interface.

    Docker is used when a participant submits reproducible code that needs to be run. YAML configuration is used to define challenge-specific requirements, while the reporting system creates HTML, PDF, CSV, and JSON outputs.

    The entire application runs locally so challenge data, reference images, masks, and participant submissions can stay on the reviewer's machine.

    Testing and reliability

    The pipeline has automated backend and frontend tests covering uploading, validation, execution, configuration, QC, reporting, exports, and challenge-specific behavior.

    It was also tested using real example submissions through the full web interface. This helped identify issues that were not obvious from automated tests alone, including batch-upload handling, duplicate ROI masks, and protecting identifying information in blinded reports.

    Project result

    The project now provides a working local workflow for taking a perfusion challenge submission from its original files through validation, optional execution, analysis, review, and export.

    The scientific results available depend on the challenge and the data provided. QC and previews can be generated for readable maps, while DCE Ktrans ROI descriptive statistics, generic reference comparisons, and provider-specific analysis or scoring become available when the required masks, references, or configured scoring tools are provided.

    Official OSIPI challenge ranking is not currently configured.
