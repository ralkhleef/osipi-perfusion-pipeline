    The problem

    A challenge team sends OSIPI a ZIP of parameter maps. Someone then has to open it, work out which challenge it is for, check the right files are there and that they open, run the team's code if they sent code, work out the numbers, and write it all up in a form that can be shared without saying who sent what.

    Doing that by hand is slow, and two people doing it will not do it the same way. The problem is not that any one check is hard. It is that there are a lot of them, they have to be done the same way every time, and the person doing them should not be able to see whose submission it is.

    This tool does those steps in a fixed order and writes down what it found.

    The steps

    StepThe question it answers
    1. UploadWhat did they send us?
    2. ReviewWhich challenge is this, and what is in the box?
    3. ValidateIs anything missing, unreadable or the wrong shape?
    4. RunIf they sent code, does it produce the maps they claim?
    5. QC and PreviewDo the numbers look sane, and how do they compare to the reference?
    6. ExportCan a reviewer read this without learning who sent it?

    Each step is described below.

    What each step does

    Upload and Review

    The archive is unpacked once and every file is written down in a list. Each file gets a job and an address. The jobs are parameter map, fitted signal and methods document. The address is dataset, participant, site and repeat.

    The address comes from the folder names first. A path like Synthetic/Participant1/Site1/Repeat1/Ktrans.nii.gz gives all four. Filename patterns fill in what the folders leave out. If the two disagree the folder wins and the clash is reported, because guessing would be worse than saying so. Nothing is worked out from the order files happen to be in. Reference and mask folders belong to OSIPI, not to the team, so they are left out of the team's file count.

    Validate

    First the files themselves: does each NIfTI open, is it the right number of dimensions, does it hold real numbers, is it empty. Then the submission as a whole, against the rules set for its challenge. An error stops the submission. A warning does not.

    Structural codes: REQUIRED_MAP_MISSING, REQUIRED_ARTIFACT_MISSING, MAP_DIMENSION_MISMATCH, ARTIFACT_DIMENSION_MISMATCH, DUPLICATE_PARAMETER_MAP, DUPLICATE_REQUIRED_ARTIFACT, DUPLICATE_METHODS_DOCUMENT, INCOMPLETE_ARTIFACT_IDENTITY, DATASET_COUNT_MISMATCH, IDENTITY_CONFLICT, UNKNOWN_DATASET.

    Run

    If the team sent a Dockerfile, their code runs in a box of its own with no network, a memory cap and a time limit. The command comes from run_config.json in the submission. Teams who only sent finished maps skip this step. If Docker is not available the step switches off and everything else still works.

    QC and Preview

    The basic health of each map: how many voxels hold a real number, how many are NaN or infinity, how many are negative. Different parameters are measured in different units, so they are reported one at a time and never averaged together.

    Where OSIPI has supplied reference maps, each submitted map is compared to it voxel by voxel and inside each ROI mask: RMSE, mean absolute error, bias and correlation.

    Each ROI also gets its own numbers for one map in one scan: median, population SD (ddof=0) and coefficient of variation (SD ÷ |mean|). These say how spread out the values are inside that one region. They are not repeatability, reproducibility or variation between participants, and the report says so, because a number in the wrong column is worse than no number. Anything that could not be worked out is written as unavailable, never as zero.

    Export

    Every format is built from one set of results, so the numbers are worked out once. The HTML and the PDF hold the same sections, the same rows and the same table numbers. You also get an ROI statistics CSV with one row per scan and region, and a combined CSV or JSON.

    A blinded export leaves out the team name, the contact address, the submission id and the archive name. Not just from the page, but from the file's own metadata and from the name it downloads under, since all three are places a name can leak.
