    Background

    A perfusion parameter map depends on the model, the fitting method and the arterial input function used to produce it. Two implementations given the same DCE scan return different Ktrans values, and the same applies to CBF and ATT derived from ASL. OSIPI runs challenges to quantify those differences and to support standardisation in clinical research.

    A comparison of that kind is only valid if every submission is handled the same way. Differences in how carefully a submission is checked, which mask it is scored against, or whether the reviewer knows its origin all become part of the result. The pipeline exists to remove those differences from the measurement.

    Pipeline overview

    A submission moves through six steps in order. Each step records what it found, and its output is available to the steps after it.

    StepPurpose
    1. UploadAccept the submission from a ZIP, a folder, a GitHub repository or a Zenodo record.
    2. ReviewDetect the challenge, index every file, and resolve each file to a scan.
    3. ValidateCheck the files individually and the submission against its challenge rules.
    4. RunExecute the submitted code in a container, where code was supplied.
    5. QC and PreviewCompute quality-control statistics and compare against reference data.
    6. ExportProduce reports and result files, blinded or unblinded.

    The steps in detail

    Upload and Review

    The archive is extracted once and indexed. Each file is recorded with a role and a scan identity. Roles are parameter map, fitted signal and methods document. A scan identity is a dataset, participant, site and repeat.

    Identity is resolved from the directory structure first. A path such as Synthetic/Participant1/Site1/Repeat1/Ktrans.nii.gz supplies all four values. Configured filename patterns fill any gaps. Where the two sources disagree, the directory takes precedence and the conflict is reported rather than resolved silently. Identity is never inferred from file order. Reference and mask directories are supplied by the organiser, so they are excluded from the submission's own artifacts.

    Validate

    File-level checks cover NIfTI readability, dimensionality, finite values and zero-byte files. Structural checks compare the submission against the rules configured for its challenge. Errors block the submission; warnings do not.

    Structural codes: REQUIRED_MAP_MISSING, REQUIRED_ARTIFACT_MISSING, MAP_DIMENSION_MISMATCH, ARTIFACT_DIMENSION_MISMATCH, DUPLICATE_PARAMETER_MAP, DUPLICATE_REQUIRED_ARTIFACT, DUPLICATE_METHODS_DOCUMENT, INCOMPLETE_ARTIFACT_IDENTITY, DATASET_COUNT_MISMATCH, IDENTITY_CONFLICT, UNKNOWN_DATASET.

    Run

    A submission containing a Dockerfile is built and run in an isolated container with no network access, a memory limit and a timeout. The command is read from run_config.json in the submission. Result-only submissions skip this step. Where Docker is unavailable the step is disabled and the remaining steps are unaffected.

    QC and Preview

    Quality control reports the proportion of finite voxels, counts of NaN and infinity, and the proportion of negative voxels for each map. Parameter types carry different units and are therefore reported separately and never averaged together.

    Where reference maps are available, each submitted map is compared against its reference voxelwise and within each ROI mask, producing RMSE, mean absolute error, bias and correlation.

    Each ROI additionally reports the median, population standard deviation (ddof=0) and coefficient of variation (SD ÷ |mean|) of one map within one scan. These describe spatial spread within a single region. They are not repeatability, reproducibility or between-participant variability, and the report states this. Values that cannot be computed are reported as unavailable rather than as zero.

    Export

    All output formats are generated from a single result model, so every figure is computed once. The HTML and PDF reports contain the same sections, rows and table numbers. Additional exports are an ROI statistics CSV with one row per scan and region, and a combined CSV or JSON in wide or long form.

    A blinded export omits the team name, contact address, submission id and archive name from the document body, the file metadata and the download filename.
