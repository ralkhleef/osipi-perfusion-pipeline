    Background

    Different analysis methods can produce different perfusion maps from the same MRI data. OSIPI challenges compare those methods. This pipeline applies the same review steps to every submission.

    Pipeline overview

    A submission moves through six steps in order. Each step records what it found, and its output is available to the steps after it.

    1

    Upload

    Accept the submission from a ZIP, a folder, a GitHub repository or a Zenodo record.

    2

    Review

    Detect the challenge, index every file, and resolve each file to a scan.

    3

    Validate

    Check the files individually and the submission against its challenge rules.

    4

    Run

    Execute the submitted code in a container, where code was supplied.

    5

    QC and Preview

    QC and previews are available for readable maps. DCE Ktrans ROI descriptive statistics can appear with compatible ROI masks, generic reference comparisons with compatible reference maps, and provider-specific analysis or scoring when configured. Official OSIPI challenge ranking is not currently configured.

    6

    Export

    Produce reports and result files, blinded or unblinded.

    The steps in detail

    Upload and Review

    The import is extracted and indexed once. Each file receives a role and, where possible, a dataset, participant, site, and repeat identity. Directory structure is used first; configured filename patterns fill gaps. Conflicts are shown to the reviewer.

    Validate

    Checks cover NIfTI readability, dimensions, finite values, zero-byte files, required content, and configured dataset structure. Errors block the submission; warnings do not.

    Validation issue codes

    REQUIRED_MAP_MISSING, REQUIRED_ARTIFACT_MISSING, MAP_DIMENSION_MISMATCH, ARTIFACT_DIMENSION_MISMATCH, DUPLICATE_PARAMETER_MAP, DUPLICATE_REQUIRED_ARTIFACT, DUPLICATE_METHODS_DOCUMENT, INCOMPLETE_ARTIFACT_IDENTITY, DATASET_COUNT_MISMATCH, IDENTITY_CONFLICT, and UNKNOWN_DATASET.

    Run

    Reproducible submissions run in an isolated Docker container with no network access, a memory limit, and a timeout. Result-only submissions skip execution and use their submitted maps.

    QC and Preview

    Readable maps receive QC and previews. QC reports finite, NaN/Inf, and negative-voxel information for each map.

    Compatible masks add DCE Ktrans ROI median, population SD, CoV, and voxel count. Compatible reference maps add whole-map and ROI bias, MAE, RMSE, correlation, error spread, overlap count, and difference maps. Missing values stay unavailable.

    DCE Ktrans ROI statistics use population SD (ddof=0) and CoV = SD ÷ |mean|. They describe spatial variation within one scan, not repeatability or reproducibility.

    Configured providers can add their own results when their assets are present. Generic reference comparison and provider results are separate. Official OSIPI challenge ranking is not currently configured.

    Export

    The HTML and PDF reports are rendered from one report model, so their values, availability states, limitations and provenance stay consistent. The PDF is a concise review summary with status and key findings first, results next, and an issues page only when review items exist. The HTML opens its summary and key results by default, while ROI results, reference comparison, additional analysis, issues and provenance stay in expandable sections. Additional exports are blinded CSV and blinded JSON results, an ROI statistics CSV with one row per scan and region, and an explicit unblinded CSV for organiser review.

    A blinded export omits the team name, contact address, submission id and archive name from the document body, the file metadata and the download filename.
