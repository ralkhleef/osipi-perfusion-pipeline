    Perfusion Challenge Pipeline

    A configurable local web application for reviewing DCE, ASL, and DSC perfusion MRI challenge submissions.

    Run locally View repository

    What the pipeline does

    The pipeline gives challenge organisers and reviewers a consistent and reproducible way to process perfusion MRI submissions.

    Submissions can be imported from a ZIP, folder/files, GitHub repository, or Zenodo record. The pipeline detects and organises the submitted files, validates them against challenge-specific requirements, and runs participant code in Docker when needed.

    It then provides map QC and previews, with additional DCE Ktrans ROI descriptive statistics, generic reference comparisons, and provider-specific analysis or scoring results when the required masks, reference maps, or configured provider assets are available. Official OSIPI challenge ranking is not currently configured. Results can be exported as PDF, HTML, CSV, and JSON reports.

    The application runs locally, so imaging data, reference maps, ROI masks, and submissions stay on the reviewer's machine.

    Submission workflows

    TypeContainsWhat happens
    Result-onlyCompleted parameter mapsMaps are validated and reviewed directly
    ReproducibleCode plus a DockerfileCode runs in Docker, then generated outputs are validated
    Batch reviewMultiple submissionsSubmissions are detected and processed separately

    DCE, ASL, and DSC are currently configured. Many challenge requirements—such as required maps, dimensions, dataset structure, and filename patterns—can be changed through config/validation_rules.yaml. New scientific formulas or provider-specific scoring logic can still require code. See Validation rules.

    Pipeline workflow

    A submission moves through six steps in order.

    1

    Upload

    Import a ZIP, folder/files, GitHub repository, or Zenodo record.

    2

    Review

    Detect the challenge, map types, submission type, and indexed files.

    3

    Validate

    Check readability, dimensions, required maps and artifacts, and challenge-specific structure.

    4

    Run

    Run reproducible submissions in Docker when needed. Result-only submissions use their existing maps.

    5

    QC and Preview

    Review map QC and visual previews. Depending on the challenge and available data, this step can also include DCE Ktrans ROI descriptive statistics, generic reference comparisons, and provider-specific analysis or scoring results. Official OSIPI challenge ranking is not currently configured.

    6

    Export

    Download blinded PDF, HTML, CSV, and JSON results, ROI statistics, or an unblinded CSV for organisers.
