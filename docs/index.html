    Perfusion Challenge Pipeline

    A configurable local web application for importing, validating, running, reviewing and exporting ASL, DCE and DSC challenge submissions.

    Run locally View repository

    What the pipeline does

    Submissions arrive as ZIP archives of NIfTI parameter maps. The pipeline extracts and indexes each archive, checks it against the rules configured for its challenge, runs the participant's code from a Dockerfile when needed, computes quality-control statistics, and exports reports as JSON, CSV, HTML and PDF. Reference comparisons and configured scoring appear only when their required data are available.

    It runs locally. Imaging data, reference maps and ROI masks stay on the machine.

    Supported submission types

    TypeContainsExecution
    Result-onlyCompleted parameter mapsSkipped, because the maps already exist
    ReproducibleCode plus a DockerfileRuns in a container, then the outputs are validated
    BatchSeveral team folders in one archiveSplit into separate submissions automatically

    DCE, ASL and DSC are configured. Adding another challenge is a change to config/validation_rules.yaml. See Validation rules.

    Pipeline workflow

    A submission moves through six steps in order.

    1

    Upload

    Accepts a ZIP, a folder, a GitHub URL or a Zenodo record.

    2

    Review

    Detects the challenge and whether the submission is result-only or reproducible, and indexes every file.

    3

    Validate

    Checks readability, dimensions, required maps and artifacts, and the expected dataset structure.

    4

    Run

    Executes reproducible submissions in Docker. Result-only submissions skip this step.

    5

    QC and Preview

    QC and previews are available for readable maps. ROI statistics, reference comparisons and scoring depend on the challenge configuration and available data.

    6

    Export

    HTML and PDF reports, blinded CSV and JSON results, ROI statistics CSV, and an explicit unblinded CSV for organisers.
