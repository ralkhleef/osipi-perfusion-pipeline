    Perfusion Challenge Pipeline

    A configurable local web application for importing, validating, running, reviewing and exporting ASL, DCE and DSC challenge submissions.

    Run locally View repository

    What the pipeline does

    Submissions arrive as ZIP archives of NIfTI parameter maps. The pipeline extracts and indexes each archive, checks it against the rules configured for its challenge, runs the participant's code in Docker when the submission includes it, computes quality-control and reference-comparison statistics, and exports reports as JSON, CSV, HTML and PDF.

    It runs locally. Imaging data, reference maps and ROI masks stay on the machine.

    Supported submission types

    TypeContainsExecution
    Result-onlyCompleted parameter mapsSkipped, because the maps already exist
    ReproducibleCode plus a DockerfileRuns in a container, then the outputs are validated
    BatchSeveral team folders in one archiveSplit into separate submissions automatically

    DCE, ASL and DSC are configured. Adding another challenge is a change to config/validation_rules.yaml. See Validation rules.

    Pipeline workflow

    Six steps, in order:

    StepWhat happens
    1. UploadAccepts a ZIP, a folder, a GitHub URL or a Zenodo record.
    2. ReviewDetects the challenge and whether the submission is result-only or reproducible, and indexes every file.
    3. ValidateChecks readability, dimensions, required maps and artifacts, and the expected dataset structure.
    4. RunExecutes reproducible submissions in Docker. Result-only submissions skip this step.
    5. QC & PreviewQuality-control statistics, image previews and reference comparison where reference data exists.
    6. ExportHTML and PDF reports, plus JSON and CSV in blinded and unblinded forms.
