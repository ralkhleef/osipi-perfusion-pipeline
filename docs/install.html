    Run the application

    Docker Desktop must be installed and running. Build the image once from the repository root, then run it. The application serves on http://localhost:8000.

    Build
    docker build -t osipi-pipeline .
    Run
    docker run --rm -p 8000:8000 \
  -v "$PWD/data:/app/data" \
  -v "$PWD/submissions:/app/submissions" \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -e PYTHONPATH=/app/backend:/app/src \
  -e HOST_SUBMISSIONS_DIR="$PWD/submissions" \
  -e HOST_OUTPUTS_DIR="$PWD/data/outputs" \
  -e HOST_REFERENCE_DATA_DIR="$PWD/data/reference_data" \
  osipi-pipeline

    Stop it with Ctrl-C. On Windows PowerShell, replace $PWD with ${PWD} and the line continuations with backticks.

    The three HOST_* variables and the Docker socket mount are what let the container start a second container for a participant's code. The backend runs inside Docker but calls the host daemon, so the volume paths it passes to docker run must be host paths, not container paths. Without these, upload, validation, QC and export still work; the Run step does not.

    The same configuration is in docker-compose.yml, which expands $PWD for you:

    Compose
    docker compose up --build     # add -d to run in the background
docker compose down

    Run the tests

    The test suite runs outside the container and needs the development dependencies:

    Tests
    pip install -r requirements.txt -r backend/requirements.txt -r requirements-test.txt
python3 -m pytest -q
