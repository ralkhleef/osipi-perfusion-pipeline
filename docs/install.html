    Requirements

    Docker and Git are the only things required to run the application. Python and Node are needed only to run the test suites, which run outside the container.

    To run the application

    Nothing else is required.

    Docker Desktop
    Must be running before docker build. Also supplies the daemon the Run step uses.
    Git
    Or download the ZIP from GitHub, which works equally well.

    To run the tests

    The suites run outside the container.

    Python 3.9 or newer
    Not needed to run the application. The image ships its own Python 3.11.
    Node 18 or newer
    Built-in modules only, so there is no npm install.

    Getting the code

    Clone
    git clone https://github.com/ralkhleef/osipi-perfusion-pipeline.git
cd osipi-perfusion-pipeline

    Every command below is run from that directory. The clone contains no imaging data: reference maps, ROI masks and submissions are excluded from version control, so a fresh clone starts empty and you supply the data yourself.

    DirectoryHolds
    backend/The FastAPI application and its services
    frontend/The browser interface, in plain HTML, CSS and JavaScript with no build step
    src/osipi_pipeline/The library: ingestion, validation and scoring
    config/Challenge rules, the file you edit to change requirements
    data/Reference data, masks, scoring packages and outputs
    submissions/Uploaded archives and their extracted contents
    tests/Python and frontend test suites

    Running the application

    There is no dependency install step: the image builds them from requirements.txt and backend/requirements.txt. Docker Desktop must be running. Build once from the repository root, then run. The application serves on http://localhost:8000.

    Build
    docker build -t osipi-pipeline .
    Run
    docker run --rm -p 8000:8000 \
  -v "$PWD/data:/app/data" \
  -v "$PWD/submissions:/app/submissions" \
  -v "$PWD/config:/app/config:ro" \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -e PYTHONPATH=/app/backend:/app/src \
  -e HOST_SUBMISSIONS_DIR="$PWD/submissions" \
  -e HOST_OUTPUTS_DIR="$PWD/data/outputs" \
  -e HOST_REFERENCE_DATA_DIR="$PWD/data/reference_data" \
  osipi-pipeline

    Stop it with Ctrl-C. On Windows PowerShell, replace $PWD with ${PWD} and the line continuations with backticks.

    The config mount is read-only and optional, since the image already contains a copy. With it, an edit to the challenge rules reaches the application on the next start instead of needing the image rebuilt. See Apply a change.

    The three HOST_* variables and the Docker socket mount are what let the container start a second container for a participant's code. The backend runs inside Docker but calls the host daemon, so the volume paths it passes to docker run must be host paths, not container paths. Without these, upload, validation, QC and export still work; the Run step does not.

    The same configuration is in docker-compose.yml, which expands $PWD for you:

    Compose
    docker compose up --build     # add -d to run in the background
docker compose down

    Verifying the install

    The container reports its own health, so a first check needs no browser and no data:

    Health
    curl http://localhost:8000/api/health

    Then open http://localhost:8000. The interface loads on the Upload step.

    SymptomUsual cause
    Cannot connect to the Docker daemon during buildDocker Desktop is not running.
    Port 8000 already allocatedSomething else holds the port. Publish another one: -p 8080:8000.
    The page loads but the Run step reports Docker unavailableThe socket mount or the HOST_* variables are missing. Everything except Run still works.
    A rules change has no effectThe image holds the old copy. See Apply a change.

    Running the tests

    The suites run outside the container, against the source in the working tree, so they need their own dependencies installed on your machine. This is the only step that installs anything with pip.

    Python tests
    pip install -r requirements.txt -r backend/requirements.txt -r requirements-test.txt
python3 -m pytest -q

    The frontend suites are plain Node scripts using only built-in modules, so there is no package to install. Each prints its own pass and fail counts and exits non-zero on a failure.

    Frontend tests
    node tests/frontend_smoke_test.js
node tests/frontend_roi_dom_test.js
node tests/frontend_validation_card_test.js
node tests/footer_logic_test.js

    To exercise the whole pipeline rather than its parts, run the demo. It builds a DCE submission, puts it through upload, validation, scoring and export, and writes the reports and CSVs to data/outputs/demo_evidence/ along with a summary of what it checked. It extracts into a temporary directory, so it leaves no submissions behind.

    End-to-end demo
    python3 scripts/demo_evidence.py
